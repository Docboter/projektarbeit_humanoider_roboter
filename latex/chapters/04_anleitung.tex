\section{Training}
\label{sec:anl-training}

Ein Training startet lokal über ein Skript, das das passende Image zieht und den Container
anlegt, oder auf einem Cluster als \acs{slurm}-Job (Batch-Skript im Auszug: \cref{anh:slurm}).
Für N1.7 wird jeweils \texttt{GROOT\_VERSION=1.7} gesetzt; auf KISSKI wird dann automatisch eine
zweite Image-Datei aus \texttt{:latest-n17} verwendet, die vorher ebenso geholt werden muss.

\begin{minted}{bash}
# lokal (Standard 30 000 Schritte); nach einem Stopp mit --resume fortsetzen
export HF_TOKEN=hf_... WANDB_API_KEY=...
./Training/setup_and_train_dockerhub_pull.sh

# KISSKI: Image einmalig holen, dann Job abschicken (4x A100, 44 000 Schritte)
apptainer pull $HOME/images/projekt-humanoider-roboter.sif \
    docker://lucam03/projekt-humanoider-roboter:latest
GLOBAL_BATCH_SIZE=32 sbatch --export=ALL Training/kisski_submit.sh
\end{minted}

Varianten werden über Umgebungsvariablen gewählt: \texttt{TUNE\_VISUAL=1} trainiert den
Bild-Encoder mit, \texttt{USE\_COTRAIN=1} mischt die Render-Datensätze bei, und
\texttt{TRAIN\_TEST\_SPLIT=1} hält die Testepisoden zurück. \texttt{Training/kisski\_chain.sh}
reiht mehrere Läufe hintereinander und wertet die Checkpoints danach nach dem Protokoll aus
\cref{sec:erg-training} aus. Der fertige Checkpoint wird mit
\texttt{Simulation/scripts/upload\_checkpoint.py} ohne Optimizer-Zustand auf Hugging Face
hochgeladen.

\section{Checkpoint messen}
\label{sec:anl-messen}

Gemessen wird auf dem Sim-Server in drei Schritten: Zuerst prüft \texttt{preflight}, ob Image
und \acs{gpu} passen. Dann folgt das visuelle Gate über drei Seeds, das in wenigen Minuten
zeigt, ob ein Modell mit Sim-Bildern zurechtkommt. Erst danach lohnt sich der Closed Loop über
20 Testlagen à 120~s, den ein Watchdog bei Hängern neu startet.

\begin{minted}{bash}
./Simulation/server_rl_run.sh preflight
# visuelles Gate, Seeds 0/1/2 (Container, GROOT_VERSION, GPU, HF-Repo ohne Konto)
tools/sim_visgate_seeds.sh groot-rl 1.6 0 groot-g1dex3-cotrain-v3-cube4-ckpt44000
python3 tools/sim_visgate_seeds_summary.py ~/groot-rl-data/sim_results \
    cotrain-v3-cube4-ckpt44000
# Closed Loop nach Protokoll (20 Testlagen x 120 s, Szene aus Lauf 70)
SIM_CUBE_EDGE=0.04 tools/sim_cl_watchdog.sh cl_meinlauf groot-rl 0 1.6 \
    luca-mue/groot-g1dex3-cotrain-v3-cube4-ckpt44000 \
    /data/checkpoints/cotrain-v3-cube4-ckpt44000
python3 tools/sim_cl_summary.py ~/groot-rl-data/sim_results/results_<...>.json
\end{minted}

\texttt{SIM\_CUBE\_EDGE=0.04} gilt nur für Modelle, die mit 4-cm-Würfeln co-trainiert wurden.
Ein Treffer bei \texttt{lifted\_clear} zählt erst, wenn das Video unter
\texttt{\textasciitilde/groot-rl-data/sim\_videos/<tag>/} einen Griff zeigt
(\cref{sec:grenzen-metriken}). Die Prüfbilder des Gates liegen nur auf dem \acs{ikr}-Server; auf
einem neuen Server müssen sie mit \texttt{server\_rl\_run.sh render} neu erzeugt werden,
das dy3-Layout mit \doc{tools/layout_shift.py --dy 0.03} (Befehle in \doc{docs/quickstart.md}).
